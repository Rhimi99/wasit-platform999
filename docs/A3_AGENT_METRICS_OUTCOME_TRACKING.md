# WASIT AI Company — A3: قياس أداء الوكلاء وتتبّع النتائج (Agent Metrics & Outcome Tracking)

> **المهمة:** `WASIT-AI-COMPANY-A3` — Agent Metrics & Outcome Tracking
> **الحالة:** ✅ مكتملة (مع فجوات `BLOCKED` موثّقة أدناه)
> **النوع:** طبقة قياس للقراءة فقط · **لا** Migration · **لا** جدول جديد · **لا** صلاحية جديدة · **لا** Tool Gateway · **لا** LLM حقيقي · **لا** ذاكرة جديدة.
> **الاعتماد:** `A1` (مفتاح الإيقاف) و`A2` (فرض نطاق الوكلاء) يبقيان فعّالين دون أي إضعاف.

---

## 1. الهدف

منح المدير العام رؤية حقيقية لأداء وكلاء شركة WASIT: كم يعملون، بمعدّل نجاح كم، بأي سرعة، وبأي كلفة فعلية، وحالتهم الصحية — مبنية **حصريًا** على بيانات مسجّلة فعلاً، دون اختلاق أي رقم.

## 2. المعمارية (Architecture)

```
┌───────────────────────────────────────────────────────────────────────┐
│                        الواجهة (Web) — GM/Admin                        │
│   AdminAiPage → تبويب "نظرة عامة" → قسم "صحة شركة الوكلاء (AI Company)" │
└───────────────────────────────▲───────────────────────────────────────┘
                                 │ GET /api/admin/ai/company-metrics
┌───────────────────────────────┴───────────────────────────────────────┐
│  admin/ai-routes.ts  —  RBAC (AI_MANAGE | ADMIN_AI) + derivePlatformScope│
└───────────────────────────────▲───────────────────────────────────────┘
                                 │ (نطاق منصّة مُشتقّ من الخادم فقط)
┌───────────────────────────────┴───────────────────────────────────────┐
│  modules/ai/agent-metrics.ts  —  buildCompanyMetrics (قراءة فقط)        │
│  يقرأ من الجداول الموجودة فقط، بلا أي كتابة                              │
└───┬───────────────┬───────────────┬───────────────┬───────────────────┘
    │               │               │               │
 agent_tasks    ai_requests     agent_run_steps   audit_logs
 (التشغيلات)   (الكلفة الفعلية)   (المحاولات)    (الاستعادة)
```

- **مصدر واحد للحقيقة للتشغيلات:** `agent_tasks` — كل صف = تشغيل واحد، يُحتسب مرة واحدة.
- **الكلفة:** من `ai_requests.cost` — سطر الدفتر الذي كتبه استدعاء المزوّد نفسه.
- **المحاولات:** من `agent_run_steps.attempt_count` (عدّاد مُثبَّت فعليًا).
- **الاستعادة:** من إجراء التدقيق `AI.AGENT_TASK_COST_RECOVERED`.
- **لا كتابة إطلاقًا:** الوحدة لا تصدّر أي دالة كتابة، ولا يمكن للوكيل تعديل أرقامه.

## 3. تعريفات المؤشرات (Metrics Definitions)

### 3.1 مؤشرات التنفيذ (Execution)
| المؤشر | التعريف | المصدر |
|---|---|---|
| Total Runs | إجمالي صفوف `agent_tasks` في النطاق | `agent_tasks` |
| Completed | الحالات `succeeded` + `approved` | `agent_tasks.status` |
| Failed | الحالات `failed` + `rejected` | `agent_tasks.status` |
| Cancelled / Blocked | أي حالة أخرى غير معروفة (لا تُختلق) | `agent_tasks.status` |
| Pending / Running | `queued`+`awaiting_approval` / `running` | `agent_tasks.status` |
| Success Rate | `Completed ÷ (Completed + Failed)`؛ **null** إذا لا تشغيلات محسومة | مشتقّ |

### 3.2 مؤشرات الأداء (Performance)
| المؤشر | التعريف |
|---|---|
| Average / Median / P95 duration | من `latency_ms` المُقاس، أو الفرق بين `created_at` و`completed_at`؛ تُهمَل القيم ≤ 0 (غير مُقاسة). |
| Slow runs | تشغيلات زمنها ≥ 10,000 ms. |
| Retry count | خطوات بـ `attempt_count > 1`. |
| Failed steps | خطوات بحالة `FAILED`. |
| Failure recovery | تشغيلات استُعيدت (دليل التدقيق). |

### 3.3 مؤشرات الكلفة (Cost)
| المؤشر | التعريف |
|---|---|
| Actual provider cost | مجموع `ai_requests.cost` المرتبطة بمهمة عبر `metadata.agentKey`. |
| Token usage | `tokens_input` / `tokens_output` من نفس الصفوف. |
| Provider / model attribution | تجميع حسب `model` (و`provider` إن توفّر). |

**قاعدة صارمة:** لا يُستخدم أي تقدير على أنه كلفة فعلية. عند غياب سجلات الدفتر تُعلَن الكلفة **«غير متاحة»**، ولا تُعرض صفرًا مُضلِّلاً.

### 3.4 الجودة والنتائج (Quality & Outcomes)
| المؤشر | التعريف |
|---|---|
| Tasks with stored result | مهام لها `result` غير فارغ (دليل أن المنفّذ أنتج مخرجات). |
| Business outcome achieved | **دائمًا 0** حاليًا — لا يوجد مصدر دليل. |

**قاعدة الإسناد (Outcome Attribution):** «المهمة اكتملت» ≠ «تحقّقت نتيجة تجارية». لا تُنسب نتيجة تجارية لوكيل إلا بدليل على أن توصيته نُفِّذت فعلاً. لا يوجد في المخطّط الحالي جدول يسجّل ذلك ⇒ القيمة 0 صراحةً، ولا تُستنتج أبدًا من اكتمال المهمة.

### 3.5 الحالة الصحية (Health)
مبنية على إشارات مُثبَّتة فقط:
| الحالة | الشرط |
|---|---|
| `no_data` | لا تشغيلات إطلاقًا. |
| `failing` | معدّل نجاح < 50% على تشغيلات محسومة. |
| `degraded` | يوجد فشل واحد على الأقل. |
| `idle` | كل التشغيلات ناجحة لكن لا نشاط خلال 24 ساعة. |
| `healthy` | كل التشغيلات ناجحة مع نشاط حديث. |

## 4. مصادر البيانات وطرق الحساب (Data Sources & Calculation)

| الجدول | ما يُقرأ | لماذا |
|---|---|---|
| `agent_tasks` | id, agent_key, status, result, latency_ms, created_at, completed_at | التشغيلات (مصدر الحقيقة) |
| `agent_registry` | key, name, requires_human_approval, is_active | الهوية/الاسم (وكيل بلا تشغيلات يظهر بـ `no_data`) |
| `ai_requests` | metadata->>'taskId'/'agentKey', model, cost, tokens, status | الكلفة الفعلية والرموز والنموذج |
| `agent_run_steps` | agent_key, status, attempt_count | إعادات المحاولة والفشل |
| `audit_logs` | action, entity_id, created_at | الاستعادة |

**لماذا لا تُقرأ `agent_metrics`؟** الجدول موجود لكن **بلا أي كاتب** في الإنتاج. لتجنّب أي احتمال ازدواج عدّ مستقبلي، لا تنضمّ هذه الوحدة إليه إطلاقًا؛ الاعتماد على `agent_tasks` وحدها يضمن أن التشغيل يُحتسب مرة واحدة.

## 5. القيود المعروفة والفجوات (Known Limitations & BLOCKED Gaps)

| الفجوة | الوصف | القرار |
|---|---|---|
| **BLOCKED-1 — كلفة مزوّد حقيقية** | لا يوجد LLM حقيقي مُفعَّل، لذا كل السجلات الحالية كلفتها 0 أو غير متاحة. البنية جاهزة لقراءة الكلفة الفعلية فور تشغيل مزوّد. | موثّق؛ لا يُختلق رقم. |
| **BLOCKED-2 — النتيجة التجارية** | لا جدول يسجّل تنفيذ توصية الوكيل، فـ «Business Outcome» = 0 دائمًا. | موثّق؛ يتطلّب مصدر دليل مستقبلي (وليس Migration عشوائيًا). |
| **BLOCKED-3 — `agent_metrics` غير مستخدم** | الجدول مُهاجَر (migration 0033) لكن بلا كاتب. لم تُضَف كتابة تجنّبًا لجدول/مهمة جديدة. | مقصود. |
| **BLOCKED-4 — عزل المالك في التجميع** | نقطة النهاية للمدير العام تُجمّع عبر المالكين بمقتضى صلاحية المنصّة (ADMIN). لا تُعرض بيانات مالك غير مخوّل. | مطابق لنموذج A2. |

## 6. الأمان والعزل (Security & Isolation)

- **مصدر موثوق:** نقطة النهاية محميّة بـ `AI_MANAGE | ADMIN_AI`، والنطاق يُشتقّ **من الخادم** عبر `derivePlatformScope` (ADMIN/SUPER_ADMIN فقط). أي طلب من غير المدير ⇒ 403.
- **لا تزوير:** لا مسار كتابة للوكيل؛ الوحدة للقراءة فقط، وكل الأرقام مشتقّة من صفوف دائمة.
- **منع تضخيم الأرقام:** التشغيل يُحتسب مرة واحدة بـ `agent_tasks`؛ لا انضمام لـ `agent_metrics`؛ إعادات المحاولة لا تُحتسب كتشغيلات جديدة.
- **عزل المستأجر:** التجميع العام يتطلّب نطاق منصّة صالحًا؛ النطاق المالك-فقط (`isPlatform=false`) يُرفض.
- **الحفاظ على A1/A2:** لم يُعدَّل `kill-switch.ts` ولا `agent-scope.ts`؛ A1 يوقف كل استدعاء مزوّد، وA2 يقيّد كل وصول بيانات.

## 7. الواجهة (GM/Admin Interface)

دُمجت المؤشرات في لوحة AI الموجودة (`AdminAiPage`) — لا واجهة منفصلة. قسم «صحة شركة الوكلاء» في تبويب «نظرة عامة» يعرض:
- إجمالي التشغيلات ومعدّل الإنجاز والفاشلة والمفتوحة.
- متوسط/وسيط الزمن والتشغيلات البطيئة.
- الكلفة الفعلية والرموز (أو «غير متاحة» بوضوح).
- قائمة «وكلاء يحتاجون انتباهك» (متدهور/فاشل).
- جدول مقارنة الوكلاء: الحالة، التشغيلات، النجاح، الزمن، الإعادات/الاستعادة، النتائج المُثبتة، الكلفة، آخر نشاط.
- حداثة البيانات (آخر نشاط / آخر قياس).
