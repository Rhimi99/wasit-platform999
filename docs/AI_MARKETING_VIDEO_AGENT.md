# Marketing Video Agent — عقد الوكيل

**المفتاح:** `marketing-video-agent` · **Tier:** `CORE_SPECIALIST` · **القسم:** `growth`
**الحالة:** مُنفَّذ للتخطيط (`executable: true`، `EXECUTOR_ACTION = plan_video`) — **لا رندر ولا نشر** (AI-FIRST-COMPLETION-02)

## 1. المهمة

تحويل هدف تسويقي إلى **خطة فيديو كاملة** — جمهور، رسالة، سكربت، ستوري بورد، قائمة أصول،
ونسخ لكل منصة — **دون إنتاج ولا نشر**. الإنتاج والنشر خطوتان منفصلتان بموافقة بشرية.

## 2. القدرات المعلنة

| القدرة | الوصف | موافقة؟ |
| --- | --- | --- |
| `plan_video` | خطة فيديو من هدف وجمهور | لا |
| `write_script` | كتابة السكربت والنصوص على الشاشة | لا |
| `build_storyboard` | تقسيم المشاهد والصور والمؤثرات الصوتية | لا |
| `prepare_delivery` | تجهيز النسخ والبيانات الوصفية للتسليم | لا |
| `render_video` | رندر الفيديو بأداة إنتاج معتمدة | **نعم** |
| `publish_video` | نشر الفيديو على منصة خارجية | **نعم** |

`video.publish` و`video.render_paid` مضافتان إلى `SENSITIVE_ACTIONS`: تُرفضان دائماً بلا موافقة
بشرية، أيّاً كان الوكيل.

## 3. البيانات والأدوات

`allowedTools` **إعلانية فقط** ولا تُمنح أي وصول على هذا الفرع (لا Tool Gateway مربوط):

- `marketing.read_catalogue_owned`, `marketing.read_brand_assets`, `video.read_assets_owned`
- `video.plan_storyboard`, `video.render_approved`, `video.publish_approved`

`scope: 'own'` — كتالوج المستدعي فقط، لا تجميعات منصة.

## 4. الحدود

| الحد | القيمة |
| --- | --- |
| تكلفة التشغيل | `maxCostUsdPerRun: 2` |
| عدد المشاهد | `maxScenesPerVideo: 12` |
| المدة | `maxDurationSeconds: 120` (وسياسة المنصة 35–120ث) |
| الصلاحيات | `ai:use` فقط — لا صلاحية جديدة |

## 5. لماذا لا يوجد منفّذ؟

القدرة الحقيقية موجودة في `lib/media/*` وتُشغَّل عبر `modules/media/routes.ts` (رندر MP4 فعلي،
تخزين خاص، روابط موقّعة، تحقق مدة من البايتات، ومحاسبة عبر `MARKETING_VIDEO`).

ربطها كمنفّذ وكيل يفتح قرارات لم تُعتمد بعد:

1. **سقف التكلفة**: هل يُحمَّل الرندر على ميزانية الوكيل أم على حساب المالك؟
2. **ملكية الأصول**: الأصول تُنسب للمنتج/البائع — من يملك نسخة الوكيل؟
3. **النشر**: أي منصة، بأي حساب، ومن يوافق؟ (اليوم: لا نشر خارجي إطلاقاً)
4. **الفصل عن Marketing Agent**: `marketing-agent` يبقى تخطيط حملات وقنوات؛ الفيديو هوية مستقلة.

هذه مسجّلة كـ`DECISION REQUIRED` في AD-049، والوضع الحالي **fail-closed**:
`agentRunRefusal` يرفض أي مهمة لهذا الوكيل، والمخطِّط يرفض أي خطة تحتويه.

## 7. منظومة الإنتاج الفعلية (جرد 2026-11-20)

الوكيل لا ينفّذ، لكن **المنظومة تعمل** ويجب أن يكون عقد الوكيل مطابقاً لها:

| الطبقة | الملف | الوظيفة |
| --- | --- | --- |
| العقد | `lib/media/video-types.ts` | `RenderSpec` (منتج/لغة/جمهور/نمط/مدة) و`RenderedVideo` و`VideoGenerationProvider` |
| المزوّد المحلي | `lib/media/video-provider.ts` → `StructuralVideoProvider` | رندر MP4 فعلي بـffmpeg + libass، خطوط عربية، بلا شبكة |
| المزوّد الفارغ | `NoopVideoProvider` | يفشل بصوت عالٍ؛ لا يُختار إلا صراحةً (`VIDEO_PROVIDER=noop`) |
| الاختيار | `lib/media/resolve.ts` | `VIDEO_PROVIDER` و`MEDIA_STORAGE` فقط — لا مزوّد Hardcoded |
| التخزين | `lib/media/local-storage.ts` | أصول خاصة داخل حدود النشر (`.wasit-media`)، لا قراءة ثابتة عامة |
| الروابط | `lib/media/tokens.ts` | توكن موقّع (HMAC-SHA256 بـ`JWT_SECRET`) مربوط بالأصل والمالك ومحدود بـ`MEDIA_DOWNLOAD_TTL_SECONDS` |
| التحقق | `lib/media/mp4.ts` | قراءة `moov/mvhd` لقياس المدة الفعلية من البايتات لا من الطلب |
| العزل | `lib/media/isolation.ts` | `.wasit-media` للإنتاج و`.wasit-media-test` للاختبار (لا تلويث متبادل) |
| السطح | `modules/media/routes.ts` | `POST /api/media/videos` (ملكية المنتج + `media:upload`) ثم قراءة/تنزيل/حذف |
| الحدود | `lib/env.ts` | `VIDEO_WIDTH/HEIGHT/FPS`, `VIDEO_FONT`/`VIDEO_ARABIC_FONT`, `MEDIA_MAX_VIDEO_BYTES=50MB`, `MEDIA_VIDEO_MAX_CONCURRENCY=2`, `RATE_LIMIT_VIDEO_MAX=6/60s` |
| المحاسبة | `lib/ai/cost-control.ts` | كل رندر يُسجَّل بـ`MARKETING_VIDEO` (usage/cost) — لا استدعاء مجاني غير محسوب |

## 8. متطلبات البيئة والتراخيص

| المتطلب | الحالة | ملاحظة |
| --- | --- | --- |
| `ffmpeg` + `libass` | يُثبَّت في صورة الـAPI (`apt`) أو `ffmpeg-static` | `VIDEO_FFMPEG_PATH` يتجاوز الاكتشاف التلقائي |
| خطوط عربية | `assets/fonts` (`Noto Sans Arabic`) | الترخيص يجب أن يُراجع قبل التوزيع (OFL) |
| ترخيص ffmpeg | بناء Debian الافتراضي LGPL | أي تفعيل لـ`--enable-gpl` (x264) يغيّر التزامات التوزيع — **قرار GM** |
| مساحة القرص | أصول محلية | لا سياسة احتفاظ/تنظيف معتمدة بعد — **قرار GM** |
| الشبكة | غير مطلوبة للرندر المحلي | مزوّد خارجي مستقبلاً يحتاج مفتاحاً وسياسة بيانات |

## 9. سير العمل التشغيلي (كما هو منفَّذ)

1. المالك يختار منتجاً يملكه ويطلب فيديو (`POST /api/media/videos`).
2. الخادم يبني `RenderSpec` من بيانات المنتج الحقيقية (اسم/وصف/سعر/عملة/بائع).
3. `StructuralVideoProvider` يرندر MP4 (حجم/معدل إطارات/مدة من الإعداد).
4. `mp4.ts` يقيس المدة الفعلية؛ تجاوز السياسة = رفض (لا أصل `READY` كاذب).
5. التخزين الخاص يحفظ الأصل؛ يُسجَّل الأصل والملكية والتكلفة.
6. المعاينة/التنزيل عبر توكن موقّع قصير العمر فقط.
7. **النشر الخارجي غير موجود**: لا قناة، لا حساب، لا موافقة معتمدة.

## 10. الفجوات والقرارات المطلوبة من المدير العام

| # | القرار | الأثر إن لم يُحسم |
| --- | --- | --- |
| 1 | سقف تكلفة الرندر ومصدرها (ميزانية الوكيل أم حساب المالك) | كل تشغيل يدوي عبر المسار الحالي |
| 2 | ملكية نسخة الوكيل من الأصل | لا يمكن نسب الأصول عند الربط |
| 3 | قناة النشر وحسابها وسياسة المراجعة | يبقى `video.publish` مرفوضاً |
| 4 | سياسة الاحتفاظ بالأصول وحذفها | نمو غير محدود للقرص |
| 5 | ترخيص توزيع ffmpeg/الخطوط | مخاطر قانونية عند التوزيع التجاري |
| 6 | الفصل عن `marketing-agent` (تخطيط حملات vs إنتاج أصول) | تداخل في المسؤولية عند ربط المنفّذ |

الوضع الحالي **fail-closed** ولا يتغيّر بأي من هذه القرارات وحدها: الربط يحتاج تعديل
`catalogue.executable` + منفّذ + عقد نطاق + اختبارات، أي مراجعة كاملة لا تفعيل ضمني. **تمّ ذلك في AI-FIRST-COMPLETION-02** (منفّذ التخطيط فقط) — انظر `docs/AI-FIRST-COMPLETION-02.md` §2.
