## 4. ما نُفِّذ

### 4.1 الخدمة — `modules/admin/entities-service.ts`

ثلاثة جداول متطابقة الشكل (`merchants` / `suppliers` / `companies`) يخدمها قارئ واحد مُعامَل بدل ثلاث نسخ،
بوصف مُصرَّح (whitelist) لأسماء الجداول والأعمدة — القيم وحدها تأتي من المستخدم.

- `entitySummary()`: لكل نوع — `total / active / inactive / verified / unverified / newLast30Days`،
  محسوبة بـ`count(*) filter (...)` في قاعدة البيانات (تغطي كل الصفوف لا الصفحة المعروضة).
- `listEntities()`: فلاتر `q` (اسم الكيان)، `status`، `verified`، `countryId`، مع pagination
  (`pageSize` ≤ 100) و`total` مستقل عن الصفحة. كل صف يحمل:
  `productCount`, `orderCount`, `gmv` عبر subqueries على `products`/`orders` بمطابقة `seller_id` + `seller_type`.
  **GMV يستثني `CANCELLED`/`REFUNDED`** — طلب ملغى ليس إيراداً.
- `getEntityDetail()`: الكيان + المالك + المقاييس (منتجات، منشور منها، طلبات، GMV، نزاعات مفتوحة وقيمتها)
  + الثقة (`trust_scores`) + آخر طلب تحقق (`verification_requests`) + أحدث 5 طلبات.
  معرّفات الشركة (`registration_number`, `tax_id`, `industry`) تُقرأ **فقط** لنوع `company`.

### 4.2 المسارات — `modules/admin/entities-routes.ts`

| المسار | الوصف |
| --- | --- |
| `GET /api/admin/entities/summary` | ملخّص الأنواع الثلاثة |
| `GET /api/admin/entities?type=…&q=&status=&verified=&countryId=&page=&pageSize=` | قائمة مُصفّاة |
| `GET /api/admin/entities/:type/:id` | تفاصيل كيان واحد |

- **RBAC:** `requireAuth` + `requireRole('ADMIN','SUPER_ADMIN')` — نفس سلطة اللوحة العامة، لا صلاحية جديدة،
  ولا تجاوز لأي مكتب متخصص (التحقق/الثقة/النزاعات تبقى بواباتها).
- **قراءة فقط:** لا POST/PATCH/DELETE. تعليق/توثيق كيان قرار يخصّ مكتباً آخر.
- **التحقق:** `zod` على الاستعلام؛ نوع مجهول/مفقود ⇒ `422 VALIDATION_ERROR`؛ كيان غير موجود ⇒ `404 NOT_FOUND`.

### 4.3 الواجهة — `/admin/entities`

- تبويبات الأنواع الثلاثة مع عدّاد إجمالي في كل تبويب، وبطاقات ملخّص (إجمالي/نشط/موقوف/موثّق/جديد 30 يوماً).
- فلاتر: بحث بالاسم، الحالة، التحقق + زر تطبيق (لا طلب عند كل حرف).
- جدول: الاسم + slug، المالك (بريد)، الدولة، الحالة/التحقق كشارات، المنتجات، الطلبات، GMV، «التفاصيل».
- لوحة تفاصيل: المالك، الدولة، تاريخ الإنشاء، المنتجات (منشور/إجمالي)، الطلبات، GMV، النزاعات المفتوحة،
  الثقة، التحقق، وحقول الشركة عند اللزوم، وأحدث الطلبات.
- ترقيم صفحات يعتمد `total` من الخادم لا عدد الصفوف المعروضة.
- **i18n:** 49 مفتاحاً × 4 لغات (ar/en/fr/zh)، والاتجاه RTL/LTR يتبع اللغة.
- `data-testid` ثابتة لكل عنصر تفاعلي لاختبار E2E.

### 5.1 فخّ اكتُشف أثناء التشغيل (وأُصلح)

النسخة الأولى حَرَست المسارات بـ`adminEntitiesRoutes.use('*', requireAuth, requireRole('ADMIN','SUPER_ADMIN'))`.
Hono يطبّق `use('*')` في تطبيق فرعي مُركَّب على `/api/admin` **على كل** مسار تحت ذلك البادئة،
فأصبحت مكاتب الطاقم المتخصصة (`/api/admin/trust`, `/api/admin/disputes`, `/api/admin/risk`,
`/api/admin/verification`) تُرفض بـ403 لـSUPPORT/RISK/DISPUTE — كشفتها الحزمة الكاملة (7 إخفاقات في
`perm01a-staff-desk-access` و`lc04-dispute-rails`). الحل: الحارس **لكل مسار** (`...guard`) بدل `use('*')`،
وهو نفس سبب وجود `isSpecializedDeskPath` في `modules/admin/routes.ts`.

## 6. ما لم يُنفَّذ في هذه الشريحة

- **لا تعليق/توثيق/تعديل كيان.** هذا قرار تشغيلي/امتثالي (من يوقف تاجراً؟ بأي سبب؟ بأي تدقيق؟)
  ويحتاج تصميم صلاحية + Audit + إشعار. الشريحة قراءة فقط عن قصد.
- **لا E2E مُشغَّل.** يحتاج `wasit_dev` + متصفحات Playwright — تغيير بيئي مقيَّد بموافقة صريحة.
- **لا شرائح 2–4** (الفئات/العملات واللغات/العمولات) — انظر §2.
