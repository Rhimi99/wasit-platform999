## أولاً: تعريف المشروع

### ما هي WASIT؟
**WASIT BUSINESS GLOBAL** («الوسيط التجاري العالمي») منصّة رقمية للوساطة التجارية تربط **الموردين والشركات وكبار التجار** بـ**صغار التجار والعملاء** عبر طبقة وساطة موثوقة. تجمع: Marketplace + B2B/B2C + Commerce + Trust + AI + Advertising + Analytics. تبدأ من **تونس** ببنية **Global-first** (الدول واللغات والعملات قابلة للتكوين، لا تونس مضمّنة في النواة).

### ما المشكلة التي تحلها؟
السوق (بدءاً بتونس) مفتّت بين تجّار وموردين صغار بلا قناة رقمية موثوقة للتعامل B2B/B2C. WASIT توفّر: اكتشاف الموردين والمنتجات، طبقة ثقة وتحقق، دورة طلب ودفع منضبطة، نزاعات بحكم واستئناف، وتحليلات لكل طرف — أي **وسيط منظّم** بين طرفين لا يثقان ببعضهما ابتداءً.

### من هم العملاء المستهدفون؟

| الطرف | الدور | القيمة التي يحصل عليها |
| --- | --- | --- |
| **المشتري (CUSTOMER)** | عميل نهائي | اكتشاف، مقارنة أسعار، طلب، دفع، تتبّع، نزاعات |
| **التاجر (MERCHANT)** | بائع صغير/متوسط | متجر، مخزون، طلبات، تحليلات، إعلانات، أدوات AI |
| **المورد (SUPPLIER)** | مصدر كتالوج | كتالوج، مشترون، تسعير |
| **الشركة (COMPANY)** | كيان أكبر | فروع، موردون، موظفون، مالية |
| **WASIT** | الوسيط | عمولة 4% + رسوم دفع + إعلانات + اشتراكات |

**الأسواق:** تونس أولاً (TND)، ثم التوسع عالمياً. **اللغات:** عربي (افتراضي)، فرنسي، إنجليزي، صيني.

### كيف تربط المشترين بالبائعين والموردين والشركات؟
1. **الاكتشاف:** المورد/التاجر ينشر الكتالوج → المشتري يجده عبر البحث والمقارنة ودليل الأطراف.
2. **الاتصال:** مراسلة مباشرة بين الطرفين.
3. **الطلب:** المشتري يُنشئ طلباً → حجز مخزون ذرّي.
4. **الدفع:** المشتري يدفع عبر مزوّد دفع معتمد (redirect — لا بطاقة تُلمس عندنا).
5. **الوساطة:** WASIT تسجّل المعاملة والعمولة في دفتر مستقل وتوفّر الثقة والنزاعات.
6. **الإغلاق:** الطلب يُنفّذ ويُسوّى.

### كيف تحقق الإيرادات؟

| المصدر | الآلية | الحالة |
| --- | --- | --- |
| **العمولة** | 4% من قيمة الصفقة = **2% بائع + 2% مشتري** (سياسة في DB، غير مضمّنة في الكود) | 🟢 منفّذ |
| **رسوم معالجة الدفع** | منفصلة عن العمولة، مع شفافية من يدفع ولمن | 🟢 منفّذ |
| **الإعلانات** | حملات (Product/Store/Supplier/Company/Top/Sponsored) | 🟢 منفّذ |
| **الاشتراكات** | مجاني · 19 TND · 99 TND · 299 TND (قيم seed قابلة للتعديل من الإدارة) | 🟢 منفّذ |
| **إيراد AI** | ميزانيات/استخدام متدرّج | 🔴 مستقبلي |

### ما حدود مسؤولية الوسيط؟ (قرارات مجمّدة)

- ❌ **لا محفظة ولا احتفاظ بأموال الأطراف** — WASIT ليس بنكاً؛ الدفتر يسجّل الحركات فقط.
- ❌ **لا تخزين بيانات بطاقات** — الدفع عبر مزوّد مرخّص.
- ❌ **لا تحويلات مالية غير معتمدة** — كل كتابة مال تمرّ بمسار واحد مُدقّق.
- ❌ **لا إدارة توصيل** — لا وحدة شحن.
- ⚖️ **العمولة قرار مالك** — لا تُغيَّر من الوكيل.

## ثانياً: الحالة العامة (12 محوراً)

> لكل محور: **الحالة** · **ما يعمل** · **ما ينقص** · **ما يمنع التقدّم**.

### 1) المنتج الأساسي
- **الحالة:** 🟢 منفّذ (بنية كاملة) · 🔵 الدليل الحيّ متوقّف (لا DB).
- **ما يعمل:** 37 وحدة خلفية، 101 جدول، 341 مسار API، 40 صفحة واجهة، 10 أدوار، 4 لغات.
- **ما ينقص:** لا سلة (Cart)، لا مسارات إدارية للتجار/الموردين/الشركات/الفئات/العملات/اللغات/العمولات.
- **ما يمنع التقدّم:** غياب إثبات تكامل حيّ في هذه الجلسة (قيد بيئي، ليس عيب كود).

### 2) تجربة المشتري
- **الحالة:** 🟡 جزئي (الدورة تعمل بمنتج واحد).
- **ما يعمل:** تصفّح، بحث، مقارنة أسعار، منتج، طلب، دفع، تتبّع، مكتبة (مفضلات/محفوظات)، نزاع.
- **ما ينقص:** 🔴 سلة/دفع متعدد البنود · 🔴 إشعار Email/SMS · 🔴 مزوّد دفع حقيقي.
- **ما يمنع التقدّم:** لا مزوّد دفع + لا قناة إشعار موثوقة.

### 3) تجربة البائع والمورد
- **الحالة:** 🟡 جزئي.
- **ما يعمل (بائع):** منتجات (إنشاء/تعديل)، مخزون، طلبات، تحليلات مبيعات، إعلانات، فيديو تسويقي، AI، ثقة/تحقق/نزاعات.
- **ما يعمل (مورد):** ملف، كتالوج، دليل، مقارنة، مراسلة.
- **ما ينقص:** 🔴 **العروض (Offers) للمورد** · 🔴 **مستحقات البائع (Payout) بلا مزوّد حقيقي** · 🟡 أسطح Finance/Reports/المشترون/التسعير Placeholder.
- **ما يمنع التقدّم:** لا مزوّد دفع (لا يمكن تحويل صافي البائع فعلياً).

### 4) الشركات وB2B
- **الحالة:** 🟡 جزئي.
- **ما يعمل:** ملف الشركة، الربط بالموردين/المشترين، طلبات، تحليلات، إعلانات، AI.
- **ما ينقص:** 🔴 الفروع (Branches)، الموظفون (Employees)، مالية الشركة، تقارير الشركة = Placeholder بلا خلفية.
- **ما يمنع التقدّم:** لا إشراف إداري على الشركات (Admin Desk ناقص).

### 5) الطلبات والمعاملات
- **الحالة:** 🟢 منفّذ ومُختبر تاريخياً.
- **ما يعمل:** إنشاء طلب، حجز مخزون ذرّي، دورة حالة كاملة (DRAFT→…→COMPLETED/REFUNDED/DISPUTED)، حارس «لا تنفيذ بلا دفع».
- **ما ينقص:** لا سلة متعددة البنود.
- **ما يمنع التقدّم:** ⛔ إثبات حيّ في هذه الجلسة (يحتاج DB).

### 6) الدفع والعمولات
- **الحالة:** 🟢 الآلية منفّذة · 🔴 المزوّد الحيّ غائب.
- **ما يعمل:** نية دفع، Webhook بـHMAC، تحقق مزدوج، عمولة 4%، دفتر، تسوية، مستحقات، مطابقة، استرداد + عكس عمولة، Webhook DLQ + Replay.
- **ما ينقص:** 🔴 لا مفاتيح مزوّد إنتاجية · 🔴 **Split لدى المزوّد غير مؤكَّد** · 🔴 لا حساب تسوية/بنكي · 🔴 استرداد ClicToPay (503) · 🟡 إتمام الدفع اليدوي DEMO-only.
- **ما يمنع التقدّم:** **تأكيد قدرة المزوّد (Split/Settlement)** + عقد + حساب بنكي.

### 7) الإدارة والمالية
- **الحالة:** 🟢 جزئي (مكتب مالية كامل، لكن Desks ناقصة).
- **ما يعمل:** لوحة إدارة، مكتب مالية (تسوية/مستحقات/مطابقة/إيصالات/إتمام يدوي)، تحليلات، اقتصاديات الوحدة، مراقبة، DLQ، سياسات، خصوصية، AI، إعلانات، اشتراكات، تدقيق.
- **ما ينقص:** 🔴 Admin Desks (تجار/موردون/شركات/فئات/عملات/لغات/عمولات) · 🔴 واجهة الضرائب · 🔴 واجهة الإيرادات.
- **ما يمنع التقدّم:** لا شيء تقني — قرار GM بتحديد الأولوية.

### 8) الأمان والثقة
- **الحالة:** 🟢 منفّذ ومُختبر تاريخياً.
- **ما يعمل:** RBAC فعلي في الخادم (10 أدوار)، جلسات + إنهاء، MFA (اختياري)، قفل حساب، CSRF، Rate limit (postgres/memory)، حماية قراءة الكيانات، تدقيق، Trust Score، Risk Engine، كشف تهرّب رسوم.
- **ما ينقص:** 🟡 **إلزام MFA للـstaff/admin** (خلف علم مطفأ افتراضياً) · 🟡 Rate limiter الافتراضي في الذاكرة (نسخة واحدة).
- **ما يمنع التقدّم:** ⚖️ قرار GM بتشغيل إلزام MFA.

### 9) الدعم والنزاعات
- **الحالة:** 🟢 النزاعات كاملة · 🔴 الدعم غائب.
- **ما يعمل:** نزاع كامل (فتح/أحداث/أدلة/رسائل/بتّ/استئناف/تنحّي صاحب القرار) + سياسات per-country.
- **ما ينقص:** 🔴 **Support Desk / تذاكر / تصعيد** (لا وحدة ولا واجهة).
- **ما يمنع التقدّم:** لا شيء تقني — قرار GM بالنطاق.

### 10) الذكاء الاصطناعي
- **الحالة:** 🟡 الوكلاء موجودون · المزوّد الحقيقي غائب.
- **ما يعمل:** 11 وكيلاً قراءة/توصية على بيانات حقيقية، ميزانية، بوابة صلاحية (T2)، جدولة، Runs/Plan/Dispatch/Recovery/Fencing، بوابة موافقة بشرية (6 وكلاء).
- **ما ينقص:** 🔴 **لا LLM حقيقي** (منطق محلي حتمي) · 🔴 Supervisor كامل · 🔴 Tool Gateway · 🔴 ذاكرة/سياق · 🔴 Kill Switch · 🟡 `scope.ts` و`supervisor-policy.ts` بلا مستدعٍ إنتاجي.
- **ما يمنع التقدّم:** 🔴 مفاتيح AI إنتاجية + قرار GM بنطاق AI.

### 11) القانون والامتثال
- **الحالة:** 🟢 البنية التقنية جاهزة · 🔴 الاعتماد القانوني غائب.
- **ما يعمل:** كتالوج 9 وثائق قانونية (إصدارات/حالة نشر)، تسجيل موافقة على إصدار محدّد، إعادة موافقة عند رفع الإصدار، حق التصحيح، بوابة إلزام مطفأة افتراضياً، موافقة كوكيز، سياسات احتفاظ per-country.
- **ما ينقص:** 🔴 **لا نصّ قانوني معتمد** (كل الوثائق `LEGAL_REVIEW_REQUIRED`) · 🔴 لا KYC/KYB/AML · 🔴 لا DPA/PCI.
- **ما يمنع التقدّم:** **محامٍ معتمد** + مزوّد هوية.

### 12) التشغيل والاستضافة
- **الحالة:** 🟡 أدوات جاهزة · 🔴 بيئة غائبة.
- **ما يعمل:** Docker/CI، health، نسخ احتياطي مشفّر (age)، استعادة، runbooks، مراقبة/tracing/alerts، سجلات.
- **ما ينقص:** 🔴 لا Staging/Production مستضافة · 🔴 لا Domain/DNS/TLS · 🔴 نسخ offsite/WAL · 🔴 Object storage · 🔴 HA/DR · 🔴 Error tracking · 🔴 قنوات Email/SMS إنتاجية.
- **ما يمنع التقدّم:** **مستضيف + نطاق** + مزوّدو خدمات.

## رابعاً: رحلات المستخدمين

> لكل رحلة: ما يستطيع فعله **اليوم** · ما لا يستطيع.

### 1) المشتري (CUSTOMER)
- ✅ **يستطيع:** التسجيل/الدخول · تصفّح السوق والفئات · البحث · مقارنة الأسعار · فتح منتج · مفضلة/حفظ · إنشاء طلب · الدفع (بيئة DEMO/manual) · تتبّع الطلب · فتح نزاع · إدارة جلسته وأمانه.
- ❌ **لا يستطيع:** شراء عدة منتجات في طلب واحد (لا سلة) · دفع ببطاقة حقيقية · استلام إشعار بريد/SMS.
- **نقطة التعطل الأساسية:** الدفع الحقيقي.

### 2) البائع (MERCHANT)
- ✅ **يستطيع:** إنشاء/تعديل منتج · إدارة المخزون · استلام الطلبات · عرض تحليلات المبيعات · إنشاء حملات إعلانية · توليد فيديو تسويقي · استخدام الوكلاء (قراءة/توصية) · طلب التحقق · متابعة الثقة · فتح/الردّ على نزاع.
- ❌ **لا يستطيع:** استلام صافي مستحقاته فعلياً (لا مزوّد دفع) · رؤية مالية/تقارير حقيقية (أسطح Placeholder).
- **نقطة التعطل الأساسية:** لا Payout بلا مزوّد.

### 3) المورد (SUPPLIER)
- ✅ **يستطيع:** ملف/شركة · كتالوج منتجات · الظهور في الدليل · مقارنة · مراسلة.
- ❌ **لا يستطيع:** نشر **عروض (Offers)** · إدارة تسعير كاملة · رؤية المشترين/التجار كأسطح تشغيلية.
- **نقطة التعطل الأساسية:** وحدة Offers غير منفّذة.

### 4) الشركة (COMPANY)
- ✅ **يستطيع:** ملف الشركة · الربط بالموردين/المشترين · الطلبات · التحليلات · الإعلانات · AI.
- ❌ **لا يستطيع:** إدارة الفروع · إدارة الموظفين · مالية الشركة · تقارير الشركة.
- **نقطة التعطل الأساسية:** أسطح Placeholder + لا إشراف إداري.

### 5) المدير العام (SUPER_ADMIN)
- ✅ **يستطيع:** إدارة المستخدمين/المنتجات/الطلبات/المعاملات/الدفتر · مكتب مالية كامل · تحليلات واقتصاديات الوحدة · مراقبة وتنبيهات · محرّكات (تحقق/ثقة/خطر/نزاعات) · AI/إعلانات/سياسات/خصوصية/اشتراكات · سجل تدقيق.
- ❌ **لا يستطيع:** إدارة التجار/الموردين/الشركات/الفئات/العملات/اللغات من لوحات مخصّصة · تعديل سياسة العمولة من الواجهة (مقصود).
- **نقطة التعطل الأساسية:** Admin Desks ناقصة.

### 6) موظف الإدارة والدعم (SUPPORT/RISK/DISPUTE/ADMIN)
- ✅ **يستطيع:** مكاتب محروسة: مراجعة تحقق · إعادة احتساب ثقة · إعادة تقييم خطر · إسناد/بتّ نزاع · مراجعة استئناف (بـrecusal).
- ❌ **لا يستطيع:** إدارة تذاكر دعم/تصعيد (لا Support Desk) · MFA مُلزم عليه افتراضياً.
- **نقطة التعطل الأساسية:** لا قناة دعم نظامية.

## خامساً: نموذج الإيرادات (بالتفصيل)

### العمولة 4%
```
قيمة الصفقة (مثال)              = 1000
  عمولة البائع (2%)             =   20
  عمولة المشتري (2%)            =   20
  إجمالي عمولة WASIT (4%)       =   40
  صافي مستحقّ البائع            =  980   (1000 − 20)
  ما يدفعه المشتري              = 1020   (1000 + 20)
```
- العمولة **سياسة في قاعدة البيانات** (`commission_policies`، سياسة `BASE`)، **غير مضمّنة في الكود**، وقابلة للتخصيص لاحقاً (نوع الحساب/البلد/العملة/الحجم…).
- المحرّك **يفشل مغلقاً**: إن لم تطابق أي سياسة فعّالة → `COMMISSION_POLICY_MISSING` (لا نسبة افتراضية).

### رسوم مزوّد الدفع — **منفصلة تماماً**
- تُحتسب من `payment_fee_policies`، مستقلة عن العمولة.
- مطلوب شفافية: **من يدفع (Payer) ولمن (Beneficiary)** لكل حركة.

### ضمانات النموذج (قرارات مجمّدة — لا تُغيَّر)
| الضمانة | المعنى |
| --- | --- |
| **لا محافظ** | WASIT لا يحتفظ برصيد عملاء. |
| **لا احتفاظ بأموال الأطراف** | لا Custody — الدفتر يسجّل فقط. |
| **لا تحويلات مالية غير معتمدة** | كل كتابة مال عبر مسار واحد مُدقّق (`applyPaymentSucceeded`/`confirmSettlement`). |
| **`مدفوع ≠ مسوّى`** | تأكيد الدفع لا يعني تحرّك المال؛ التسوية تحتاج دليل تحويل. |
| **العمولة قرار مالك** | لا يعدّلها الوكيل. |
