## 2. الهدف

بناء **Agent Supervisor** يقود `Agent Runs` **بالاعتماد الحصري على المكونات الموجودة**:

| المكوّن | الموقع | الدور في القيادة |
| --- | --- | --- |
| `planAgentRun` | `modules/ai/planner.ts` | إنشاء Run من هدف + خطوات مقترحة (يُثبَّت `PLANNING`، ولا يُنفّذ) |
| `dispatchStep` | `modules/ai/dispatcher.ts` | إرسال خطوة مؤهَّلة واحدة إلى نظام المهام الحالي (مطالبة ذرّية + Fencing) |
| `reconcileRun` | `modules/ai/dispatcher.ts` | تخطّي التابع عند فشل المتطلّب + إغلاق Run بالحالة الصادقة |
| `recoverStuckSteps` / `recoverRun` | `modules/ai/dispatcher.ts` + `lib/scheduler.ts` | استعادة الخطوات العالقة `RUNNING` بعد تعطّل العملية |
| `approveRunStep` | `modules/ai/dispatcher.ts` | الموافقة البشرية على الخطوات الحساسة (تبقى فعلاً بشرياً) |

**قرار الإصدار:** الإصدار الأول **deterministic فقط** — يقود خطة **محفوظة ومتحقَّق منها** (DAG + تبعيات)
**دون أي LLM**. توليد الخطة يبقى مسؤولية المستدعي (يُمرَّر كخطوات مقترحة إلى `planAgentRun`).

**لا نظام موازٍ:** لا Executor جديد، لا طابور جديد، لا مسار مهام ثانٍ.

## 3. المسؤولية وحدود السلطة (إلزامية)

Supervisor:

1. **ينسّق** تنفيذ الخطوات وفق الـDAG والتبعيات (بالترتيب الطوبولوجي الحتمي من AI-02.2).
2. **لا يملك صلاحيات أعلى من الوكلاء**: يعمل باسم طالب التشغيل (`run.requestedBy`)؛ كل إرسال يمرّ
   بـ`dispatchStep` الذي يعيد فحص صلاحيات الطالب مقابل متطلبات الوكيل في كل مرة.
3. **لا يغيّر** هوية الوكيل أو اختصاصه أو نطاق بياناته.
4. **لا يتجاوز** RBAC أو الموافقات أو Tool Policies.
5. **لا ينفّذ** عملية محظورة عبر وكيل آخر (لا يختار وكيلاً غير المخطَّط له).
6. **لا يوافق** على طلب أنشأه بنفسه — **لا يستدعي `approveRunStep` إطلاقاً**؛ الموافقة تبقى فعلاً بشرياً
   من معتمِد مخوّل مختلف (حماية AI-02.P0).
7. **يعيد التحقق** من الصلاحيات والسياسات عند **كل** عملية تنفيذ (عبر `dispatchStep`، لا يثق بحالة مخزّنة).

**هوية التدقيق:** يُسجَّل Supervisor كفاعل `SYSTEM` (كما تفعل دورة الاستعادة)، **بينما تبقى السلطة**
لطالب التشغيل. لا انتحال هوية موافق، ولا رفع صلاحية.

## 4. سلامة التنسيق والتزامن (تصميم الحماية المطلوب)

**مبدأ ملزم:** **لا يُعتمد in-memory mutex كضمان التزامن الوحيد.** الضمان صالح **عبر عمليات Server متعددة**
(قاعدة البيانات هي الحكم)، تماماً كما في AI-02.3.2.

| الخطر | آلية الحماية المطلوبة (على مستوى قاعدة البيانات) |
| --- | --- |
| **تشغيل Supervisor مرتين على Run واحد** | (أ) **قفل استشاري للـRun** `pg_advisory_xact_lock(hash(runId))` (بلا تغيير مخطط) يُسلسل مشغّلين اثنين؛ **و** (ب) مطالبة الخطوة الذرّية في `dispatchStep` (`UPDATE … WHERE status IN ('PENDING','READY') RETURNING`) تضمن **فائزاً واحداً** للخطوة. الاثنان معاً: لا تقدّم مزدوج ولا مهمة مكرّرة. |
| **تكرار Dispatch / إنشاء Agent Tasks** | المطالبة الذرّية (token = `attempt_count`) + حارس `findTaskForStep` (خطوة لها مهمة ⇒ رفض) + `createAgentTask(..., fencing)` في **معاملة واحدة** (AI-02.3.2). |
| **فقدان التقدّم بعد تعطّل العملية** | الدورة **idempotent وقابلة للاستئناف**: لا حالة تقدّم في الذاكرة؛ الحالة كلها في `agent_runs`/`agent_run_steps`. دورة الاستعادة الحالية (`recoverStuckSteps`) تسدّ الخطوات العالقة `RUNNING`. |
| **حلقات التنسيق غير المحدودة** | سقف صارم للتمريرات لكل Run = **عدد الخطوات** (`≤ MAX_PLAN_STEPS = 25`) + شرط تقدّم: إن لم يتغيّر شيء في تمريرة ⇒ توقّف فوري. لا `while(true)`. |
| **إعلان نجاح Run قبل التحقق من جميع الخطوات** | Supervisor **لا يُغلق Run بنفسه أبداً**؛ الإغلاق حصراً عبر `reconcileRun` الذي يشترط أن **كل الخطوات محسومة** (و`COMPLETED` يمرّ بـ`assertRunCompletion` من AI-02.1). |

**ملاحظة تصميمية (نافذة التنفيذ المتزامن):** تنفيذ Executor **متزامن** داخل `createAgentTask`
(دالة `executeAgentTask` تُنتظر قبل إرجاع المهمة)، لذا عند عودة `dispatchStep` تكون الخطوة **محسومة فعلاً**؛
دور Supervisor يبقى: اختيار الخطوة المؤهَّلة التالية ← إرسالها ← `reconcileRun` ← التكرار. هذا **يبسّط** القيادة
ويُقلّل النوافذ، دون إضعاف ضمانات AI-02.3.2.

## 5. حدود الإصدار

### داخل النطاق
- **Orchestration Core**: خدمة `modules/ai/supervisor.ts` تقود Run محفوظاً خطوةً خطوة.
- **إنشاء Run** من هدف + خطة صالحة (عبر `planAgentRun`).
- **قيادة الخطوات المؤهَّلة** (تبعياتها `SUCCEEDED`) بالترتيب الطوبولوجي.
- **التوقّف عند الموافقات**: عند مصادفة خطوة `requiresApproval` غير معتمَدة، تتوقف التمريرة (لا تجاوز).
- **Reconciliation** حتى الحالة النهائية (عبر `reconcileRun`).
- **تتبّع وتدقيق** مراحل التنسيق (Audit لكل تمريرة/تقدّم + سجل دورة).
- **أقل سطح API إداري لازم** — إذا أثبتت مراجعة البنية ضرورته (انظر §7 القرار B).

### خارج النطاق (مؤجّل صراحةً)
- **LLM Planner** (توليد الخطة تلقائياً) · **Tool Gateway** · **Retry / Backoff / Circuit Breaker**.
- **Kill Switch** · **AI Provider configuration** · **تغيير ترتيب الوكلاء أو اختصاصاتهم** (AI-05).
- **واجهة Supervisor إدارية شاملة** (UI).
- **أي Migration أو عمود/جدول جديد** — القيادة تُبنى على المخطط القائم.
