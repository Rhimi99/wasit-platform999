# 3. الإغلاق الآمن — `session-close`

## الغرض

يمنع إنهاء الجلسة والعمل موجود في مكان واحد فقط. لا يُصلح شيئًا بنفسه:
يطبع الأسباب ويخرج بخطأ.

```bash
./scripts/session/session close
```

رموز الخروج: `0` آمن للإغلاق · `1` غير آمن.

## شروط النجاح

| الشرط | التفصيل |
| --- | --- |
| لا تعارضات | `git ls-files --unmerged` فارغ |
| شجرة نظيفة | لا staged / unstaged / untracked |
| لا stashes | أو تم الاعتراف بها |
| لا commits غير مدفوعة | `origin/<branch>..HEAD` فارغ |
| GitHub مؤكَّد | `fetch` نجح و`origin/<branch>` == HEAD |
| لا ملفات مهمة غير محفوظة | أو تم الاعتراف بها |

## الخيارات

| الخيار | الاستخدام |
| --- | --- |
| `--no-fetch` | **لا يُستخدم للنجاح**: الإغلاق غير المتحقَّق يُعدّ فاشلًا بالتصميم |
| `--ack-ignored` | تتحمّل المسؤولية عن `.env`/dumps/الوسائط (الأداة **لا** تتحقق من وجود نسخة خارجية) |
| `--ack-stash` | أنت راجعت الـstash وتركتها عن قصد |

## ماذا يعني كل فشل

```
✖ NOT SAFE TO CLOSE:
  • 3 commit(s) are not on origin/master
  • working tree is not clean (0 staged / 2 unstaged / 1 untracked)
```
- **commits غير مدفوعة** → `./scripts/session/session checkpoint --push-only`
- **شجرة غير نظيفة** → راجع الملفات ثم checkpoint، أو bundle إن كانت لا تُرفع
- **ملفات مهمة غير محفوظة** → انسخها إلى تخزين دائم (انظر [النسخ الاحتياطي](05-backup.md)) ثم `--ack-ignored`
- **fetch فشل** → أصلح الشبكة؛ لا تغلق الجلسة على حالة غير متحقَّقة

## معنى «آمن»

آمن = *كل ما أنتجته هذه الجلسة موجود على GitHub*، وليس «لا أخطاء في الشجرة».
لهذا يفشل الأمر عند تعذّر الاتصال بـGitHub حتى لو كانت الشجرة نظيفة.

## قبل الإغلاق — قائمة سريعة

1. `./scripts/session/session close` → إن نجح، انتهيت.
2. إن فشل: عالج السبب (لا تتجاوز الفحص).
3. عند وجود ملفات متجاهَلة مهمة: `./scripts/session/session backup` ثم انسخ
   الملفات نفسها إلى مخزن خارجي، ثم أعد الإغلاق مع `--ack-ignored`.
