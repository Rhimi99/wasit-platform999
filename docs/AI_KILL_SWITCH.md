# WASIT AI COMPANY — A1: مفتاح إيقاف الذكاء الاصطناعي المركزي (AI Kill Switch)

> **الحالة:** مُنفَّذ (A1) — أول مهمة تنفيذية في خارطة WASIT AI Company.
> **النوع:** ضابط أمان (Safety Control). **لا يمنح أي صلاحيات جديدة.**
> **التاريخ:** 2026-11-19 · **الفرع:** `master` @ `98c3a958…`

---

## 1. الهدف

آلية مركزية **واحدة** تتيح للمدير العام أو مسؤول التشغيل **إيقاف كل عمليات الذكاء الاصطناعي** فوراً عند أي خلل أو تجاوز أو سلوك غير متوقّع، ثم إعادة تفعيلها بأمان.

**المبدأ الحاكم:** الإيقاف **لا يعتمد على الـLLM** (مفتاح منطقي بحت)، و**يفشل مغلقاً** (fail-closed): أي عطل في قراءة الحالة ⇒ **منع التنفيذ**، لا السماح به.

---

## 2. مكان التحكم (نقطة واحدة مركزية)

| البند | القيمة |
| --- | --- |
| **الوحدة** | `packages/server/src/lib/ai/kill-switch.ts` |
| **الدالة الحارسة** | `assertAiExecutionEnabled()` — ترمي `ApiError` (503 `SERVICE_UNAVAILABLE`) |
| **دالة الفحص** | `isAiExecutionBlocked()` — للفروع التي تسجّل رفضها بنفسها |

| **المُهيّئ (seed)** | متغيّر البيئة `AI_AGENT_EXECUTION_ENABLED` (افتراضي `true`) |
| **واجهة الإدارة** | `GET/POST /api/admin/ai/kill-switch` |
| **واجهة المستخدم** | تبويب «نظرة عامة» في `AdminAiPage` — بطاقة إيقاف/تفعيل بحالة واضحة |

---

## 3. الصلاحيات

- الوصول إلى مسار الإدارة محكوم بـ **`AI_MANAGE` أو `ADMIN_AI`** (نفس بوابة `/api/admin/ai/*`).
- **`SUPER_ADMIN`** يملك كل الصلاحيات ⇒ يستطيع التحكم.
- **`ADMIN`** يملك `AI_MANAGE` و`ADMIN_AI` ⇒ يستطيع التحكم.
- **`CUSTOMER`/`MERCHANT`/`SUPPLIER`/`SUPPORT`** ⇒ **403** قبل الوصول إلى المعالج.
- **غير مصادَق** ⇒ **401**.
- **الإيقاف ليس صلاحية**: لا يمنح أي وكيل قدرة جديدة، ولا يُلغي RBAC أو الموافقات أو الميزانيات.

## 4. نقاط التنفيذ المحمية (كلها تُفحص)

| النقطة | الملف | السلوك عند الإيقاف |
| --- | --- | --- |
| إنشاء مهمة وكيل (مباشر/مجدول/موافقة) | `modules/ai/agents.ts` → `createAgentTask` | **رفض 503** — لا صف مهمة جديد |
| اعتماد مهمة (تشغيلها) | `agents.ts` → `decideAgentTask` | **رفض 503** عند APPROVE (REJECT يبقى مسموحاً) |
| تخطيط Run جديد | `modules/ai/planner.ts` → `planAgentRun` | **رفض 503** — لا Run/Step جديد |
| إرسال خطوة (Dispatch) | `modules/ai/dispatcher.ts` → `dispatchStep` | **رفض 503** — لا انتقال إلى RUNNING |
| التشغيل المجدول | `modules/ai/scheduling.ts` → `runDueAgentSchedules` | **no-op** + سجل رفض واحد |
| المشرف (Supervisor) | `modules/ai/supervisor.ts` → `runSupervisorCycle` | **no-op** + سجل رفض واحد |
| إعادة المحاولة (Retry) | `supervisor.ts` → `retryStep` | **لا إعادة** — لا استهلاك للمحاولة، لا Dispatch |
| استعادة الخطوات العالقة | `dispatcher.ts` → `recoverStuckSteps` | **no-op** + سجل رفض واحد |
| استعادة Run يدوياً | `dispatcher.ts` → `recoverRun` | **رفض 503** |
| **الشبكة الأعمق:** أي استدعاء مزوّد | `lib/ai/runtime.ts` → `runAIFeature` | **رفض 503** — لا استدعاء مزوّد ولا قيد كلفة |

> **الفحص عند كل خطوة تنفيذ، لا عند بداية المهمة فقط:** كل نقطة أعلاه تُفحص لحظة تنفيذها. لذلك Run متعدد الخطوات **يتوقف قبل الخطوة التالية** عند تفعيل الإيقاف، ويستأنف بعد إعادة التفعيل.

---

## 5. ما الذي يتوقف وما الذي **لا يمكن** إلغاؤه

### يتوقف فوراً
- إنشاء أي مهمة AI جديدة.
- إرسال أي خطوة جديدة في Run قيد التنفيذ.
- التشغيل المجدول والمشرف وإعادة المحاولة والاستعادة.
- أي استدعاء لمزوّد LLM (حتى `/api/ai/run` المباشر).

### لا يتوقف / لا يُلغى
- **المهام والخطوات الجارية لا تُحذف ولا تُتلف** — تبقى حالتها قابلة للتتبّع كما هي.
- **لا يُدّعى إلغاء عملية خارجية بدأت بالفعل.** إذا كان Executor قد بدأ استدعاءً لا يمكن إلغاؤه بأمان، **تُوثَّق الحالة بوضوح** ولا تُتابَع الخطوات اللاحقة (لأن `dispatchStep` و`runAIFeature` يرفضان لاحقاً).
- بيانات AI السابقة (سجلّات، نتائج) تبقى سليمة.

---

## 6. آلية إعادة التشغيل (Resume)

1. يعيد المسؤول المصرّح التفعيل: `POST /api/admin/ai/kill-switch { enabled: true }` (أو يرفع `AI_AGENT_EXECUTION_ENABLED=true` ويعيد تشغيل الخدمة).
2. **لا إعادة تنفيذ مزدوجة:** لأن الإيقاف يرفض **قبل** أي انتقال حالة (لا خطوة تنتقل إلى RUNNING، لا مهمة تُنشأ، لا محاولة تُستهلك)، فإن إعادة التفعيل تُترك الحالة كما كانت بالضبط؛ الخطوة التالية تُنفَّذ **مرة واحدة** عبر آلية الإرسال الحالية (المحميّة بقفل DB والمُعرّف بـ`claimToken`).
3. الجداول لم تُفقد: تبقى نشطة و«مستحقة»، ويعالجها الاجتياح التالي بعد التفعيل.

---

## 7. حدود الحماية (Fail-closed)

- **مفتاح منطقي في الذاكرة** ⇒ لا يعتمد على مزوّد، ولا على قاعدة بيانات، ولا على استدعاء شبكي.
- **فشل قراءة الحالة ⇒ منع** (وليس سماح): مُغلَّف بـ`try/catch` يعيد `false` عند أي خطأ غير متوقّع.
- **لا تجاوز عبر مسار آخر:** كل سطح (API، مجدول، مشرف، استعادة) يمرّ عبر نفس الوحدة؛ والشبكة الأعمق `runAIFeature` تُغلق أي مسار منسِيّ.
- **لا يعتمد على ذاكرة عملية واحدة فقط؟** — **جزئياً:** المفتاح **عام على مستوى العملية**، فيوقف كل الأسطح في نفس العملية. لكنه **لا ينتشر تلقائياً بين عمليات/نسخ متعددة** (انظر §9 BLOCKED).

## 8. سجل التدقيق (Audit)

يُستخدم نظام `writeAudit` الموجود (لا نظام سجلّات جديد). الأحداث:

| الحدث | متى |
| --- | --- |
| `AI.KILL_SWITCH_DISABLED` | تفعيل الإيقاف عبر واجهة الإدارة |
| `AI.KILL_SWITCH_ENABLED` | إعادة التفعيل عبر واجهة الإدارة |
| `AI.KILL_SWITCH_SCHEDULE_REFUSED` | رفض اجتياح مجدول (سجل واحد لكل اجتياح) |
| `AI.KILL_SWITCH_SUPERVISOR_REFUSED` | رفض دورة المشرف (سجل واحد) |
| `AI.KILL_SWITCH_RECOVERY_REFUSED` | رفض اجتياح الاستعادة (سجل واحد) |

> **لا secrets ولا API keys ولا بيانات حساسة** في أي سجل. السبب (`reason`) نصّ حر قصير اختياري فقط.

**ملاحظة تصميمية:** المسارات التي **ترمي 503** (إنشاء/إرسال/تخطيط/استعادة يدوية) لا تُسجّل رفضاً من داخل الوحدة المركزية؛ الرمي نفسه هو الإشارة، ويظهر في سجل الطلب/المراقبة. أما **الاجتياحات الخلفية** (مجدول/مشرف/استعادة) فتُسجّل رفضاً صريحاً مرة واحدة لكل دورة، لأنها لا تُنتج استجابة HTTP يراها المشغّل.

---

## 9. الأجزاء BLOCKED (تحتاج قراراً / بنية)

> **قيد هذه المهمة:** لا Migrations ولا جداول جديدة.

- **BLOCKED — الإيقاف عبر نسخ متعددة (Fleet-wide):** المفتاح في الذاكرة لا ينتشر بين عمليات متعددة (مثلاً عدة replicas للـAPI، أو عمليات worker منفصلة). **التصميم المطلوب:** جدول إعدادات مشترك (مفتاح/قيمة) أو سجل حالة DB، يُقرأ في `assertAiExecutionEnabled` مع كاش قصير، وكتابة تتحقق بشرط (conditional write) عند التبديل + بثّ/إبطال الكاش. **يتطلب Migration ⇒ مؤجّل بقرار GM.**
- **الملاحظة ذاتها تنطبق** على الاستمرارية عبر إعادة التشغيل: الحالة الحالية تُعاد إلى قيمة `AI_AGENT_EXECUTION_ENABLED` عند إعادة تشغيل العملية.
