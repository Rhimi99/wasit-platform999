## 1. WASIT — من نحن

**WASIT BUSINESS GLOBAL (الوسيط للتجارة الرقمية)** — منصة وساطة تجارية رقمية تربط المشترين بالمورّدين والتجار والشركات، وتدير دورة الصفقة كاملة: من التسجيل والتوثيق، إلى العرض والطلب، إلى العمولة والدفع والدفتر والتسوية والصرف.

```
        Buyer  ◄────────►  WASIT  ◄────────►  Seller / Supplier / Company
                     طبقة الوساطة الرقمية
```

**في أربع نقاط:**
- **منصة وسيط تجاري رقمي** — ليست شركة توصيل، وليست بنكًا.
- **B2B + B2C** في نظام واحد.
- **عربية أولًا** (RTL) مع دعم fr/en، وبنية Global-first قابلة للتوسع الدولي.
- **مبنية ومختبرة فعليًا** — وليست فكرة على ورق.

## 2. Problem — المشكلة

| المشكلة | الأثر على التاجر والشركة |
| --- | --- |
| صعوبة الوصول إلى موردين وأسواق جديدة | نمو مقيّد بالعلاقات الشخصية |
| تشتّت عمليات التجارة | عرض، طلب، فاتورة، دفع، تسوية — أدوات منفصلة بلا أثر موحّد |
| ضعف الثقة بين الأطراف | لا إشارات ثقة قابلة للتفسير ولا مسار منظّم عند الخلاف |
| صعوبة الوصول إلى فرص B2B | فرص ضائعة لغياب المطابقة والبحث الموحّد |
| غياب وسيط رقمي منظّم | قواعد غير معلنة وعمولات غير قابلة للتدقيق |

> لا تتضمّن هذه الوثيقة أي إحصاءات سوقية — المشروع لا يحتوي على دراسة سوق موثّقة.

## 3. Solution — الحل

**طبقة وساطة رقمية واحدة** تُدير الصفقة كاملة، بقواعد معلنة وقابلة للتدقيق.

**ما تفعله WASIT:**
- تربط المشتري بالبائع الصحيح (بحث، تصنيف، مطابقة، مقارنة أسعار).
- تدير الطلب والعرض والمخزون.
- تحتسب العمولة بقاعدة واضحة من قاعدة البيانات.
- تفصل الدفع عن التسوية عن العمولة المستحقة عن العمولة المستلمة.
- تسجّل كل حركة مالية بأطرافها (Payer / Beneficiary) في دفتر الحسابات.
- تدير الثقة والتوثيق والمخاطر والنزاعات والإعلانات والاشتراكات.

**ما لا تفعله WASIT:**
- ليست شركة توصيل، ولا طرفًا لوجستيًا.
- لا تحتفظ بأرصدة للعملاء (**لا Wallet**).
- لا تتحمّل تلقائيًا مسؤولية اتفاق خارج المنصة.

## 4. How It Works — كيف تعمل

```
Registration → Verification → Product/Offer → Order
    → Commission → Payment → Ledger → Settlement → Payout
```

| المرحلة | ما يحدث |
| --- | --- |
| **التسجيل** | حساب + جلسة آمنة + دور |
| **التوثيق** | مستويات توثيق وسياسات |
| **العرض** | منتج، تصنيف، حد أدنى للكمية (MOQ) |
| **الطلب** | طلب مؤكَّد بالأطراف |
| **العمولة** | احتساب من سياسة قاعدة البيانات |
| **الدفع** | نيّة دفع + تأكيد مزوّد/Webhook موقّع |
| **الدفتر** | تسجيل الحركة بأطرافها |
| **التسوية** | تأكيد التسوية بدليل إلزامي |
| **الصرف** | صرف مستحق البائع |

**مبدأ محفوظ:** الدفع ≠ التسوية ≠ العمولة المستحقة ≠ العمولة المستلمة — أربع حالات منفصلة، والنظام مُختبر على أنه لا يفبرك أي حالة مُسوّاة.

## 5. Business Model — نموذج الأعمال

### العمولة — المصدر الأساسي

**4% من قيمة الصفقة إجمالًا = 2% على البائع + 2% على المشتري**

| البند | القيمة |
| --- | --- |
| قيمة الصفقة | 210.0000 |
| العمولة الإجمالية (4%) | 8.4000 |
| حصة المشتري (2%) | 4.2000 |
| الإجمالي النهائي | 214.2000 |

> أرقام حقيقية من طلب فعلي في قاعدة بيانات العرض.

**مزايا النموذج:**
- العمولة **سياسة في قاعدة البيانات** لا كود مُثبّت → قابلة للتعديل إداريًا مع تدقيق.
- المحرّك **يفشل مغلقًا** إن غابت السياسة — لا رقم مخترع.
- **رسوم مزوّد الدفع منفصلة تمامًا** عن عمولة WASIT.

**مصادر إضافية مُنَمذجة:** رسوم معالجة الدفع · الإعلانات · الاشتراكات (0 / 19 / 99 / 299 TND كأسعار تهيئة).
