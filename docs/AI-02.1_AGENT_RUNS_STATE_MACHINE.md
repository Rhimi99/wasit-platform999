## 1. الغرض

توفير نموذج بيانات موثوق لـ**تشغيل مركّب واحد** (orchestration) يتكوّن من عدة خطوات وكلاء، مع **آلة حالات محكمة**. هذه هي الأرضية التي سيبني عليها `Agent Supervisor` لاحقًا. لا يُبنى في هذه المرحلة أي منطق للتخطيط (`planRun`) أو الإرسال (`dispatchStep`) أو التنفيذ التلقائي.

## 2. الجداول

### 2.1 `agent_runs` — التشغيل الواحد

| الحقل | النوع | الوصف |
| --- | --- | --- |
| `id` | `varchar(36)` PK | معرّف UUID |
| `run_key` | `varchar(128)` NOT NULL | مفتاح idempotency فريد — يمنع فتح تشغيلين لنفس الطلب |
| `title` | `varchar(300)` NOT NULL | هدف مختصر (مثال: "إطلاق منتج X في فرنسا") |
| `description` | `text` | سياق/تعليمات موسّعة |
| `status` | `agent_run_status` NOT NULL DEFAULT `DRAFT` | حالة دورة الحياة |
| `requested_by` | `varchar(36)` NOT NULL | **هوية الطالب البشري** — لا تُستبدل بهوية `SYSTEM` |
| `summary` | `jsonb` | الملخّص المجمّع عند الوصول لحالة نهائية |
| `error` | `jsonb` | تفاصيل الفشل عند الحاجة |
| `metadata` | `jsonb` | بيانات وصفية إضافية |
| `started_at` / `completed_at` | `timestamptz` | زمن البدء/الإكمال |
| `created_at` / `updated_at` | `timestamptz` NOT NULL DEFAULT `now()` | الطوابع الزمنية |

**الفهارس:** `run_key` (فريد)، `requested_by`، `status`، `created_at`.

### 2.2 `agent_run_steps` — خطوات التشغيل

| الحقل | النوع | الوصف |
| --- | --- | --- |
| `id` | `varchar(36)` PK | معرّف UUID |
| `run_id` | `varchar(36)` NOT NULL | FK → `agent_runs.id` (`ON DELETE CASCADE`) |
| `step_key` | `varchar(64)` NOT NULL | مفتاح ثابت للخطوة داخل التشغيل |
| `agent_key` | `varchar(64)` NOT NULL | الوكيل المتخصّص المنفّذ (يُتحقّق منه في مرحلة التخطيط لاحقًا) |
| `status` | `agent_run_step_status` NOT NULL DEFAULT `PENDING` | حالة الخطوة |
| `input` | `jsonb` NOT NULL | مدخلات الخطوة |
| `result` / `error` | `jsonb` | النتيجة/الفشل |
| `priority` | `integer` NOT NULL DEFAULT `0` | ترتيب التنفيذ (الأعلى أولًا) |
| `attempt_count` / `max_attempts` | `integer` NOT NULL DEFAULT `0` / `1` | عدّاد المحاولات وحدّها |
| `depends_on` | `jsonb` NOT NULL DEFAULT `[]` | قائمة `stepKey` للتبعيات داخل نفس التشغيل |
| `requires_approval` | `boolean` NOT NULL DEFAULT `false` | هل تحتاج موافقة بشرية |
| `approved_by` | `varchar(36)` | هوية المعتمِد |
| `started_at` / `completed_at` | `timestamptz` | زمن البدء/الإكمال |
| `created_at` / `updated_at` | `timestamptz` NOT NULL DEFAULT `now()` | الطوابع الزمنية |

**العلاقات والقيود:**
- **FK:** `run_id` → `agent_runs.id` مع `ON DELETE CASCADE` (حذف تشغيل غير مُبدأ يحذف خطواته، ولا يترك يتامى). هذه أول FK صريح في المستودع؛ باقي الجداول تعتمد سلامة مرجعية على مستوى التطبيق، وهنا نُثبّتها في القاعدة لأن التشغيل/الخطوة وحدة ذرّية.
- **فريد:** `(run_id, step_key)` — لا تكرار لنفس الخطوة داخل التشغيل.
- **CHECK `priority >= 0`** — منع قيم الأولوية غير الصالحة.
- **CHECK `attempt_count >= 0 AND max_attempts >= 1 AND attempt_count <= max_attempts`** — منع قيم المحاولات غير الصالحة.
- **CHECK `jsonb_typeof(depends_on) = 'array'`** — `depends_on` مصفوفة دائمًا.
- **الفهارس:** `(run_id, step_key)` فريد، `run_id`، `agent_key`، `status`.

> **ملاحظة تصميم:** سلامة التبعيات (عدم وجود تبعية دائرية/غير معروفة) **لا تُفرض في القاعدة** لأن الدورية عبر الصفوف لا تُعبَّر عنها بـ`CHECK`. تُفرض في دالة التحقق على مستوى التشغيل (`assertValidDependencies`) — مكانها الصحيح قبل الحفظ.

## 3. آلة الحالات

التعريف المركزي في `packages/server/src/modules/ai/run-state-machine.ts` (منطق صرف: لا قاعدة بيانات ولا تنفيذ).

### 3.1 حالات التشغيل (11)

`DRAFT` → `PLANNING` → `AWAITING_APPROVAL` → `DISPATCHING` → `RUNNING` → `PAUSED` → `AGGREGATING` → `COMPLETED` / `PARTIALLY_COMPLETED` / `FAILED` / `CANCELLED`.

**الانتقالات القانونية:**

| من | إلى |
| --- | --- |
| `DRAFT` | `PLANNING`, `CANCELLED` |
| `PLANNING` | `AWAITING_APPROVAL`, `DISPATCHING`, `FAILED`, `CANCELLED` |
| `AWAITING_APPROVAL` | `PLANNING`, `DISPATCHING`, `FAILED`, `CANCELLED` |
| `DISPATCHING` | `RUNNING`, `PAUSED`, `FAILED`, `CANCELLED` |
| `RUNNING` | `AGGREGATING`, `PAUSED`, `FAILED`, `CANCELLED` |
| `PAUSED` | `DISPATCHING`, `RUNNING`, `AGGREGATING`, `FAILED`, `CANCELLED` |
| `AGGREGATING` | `COMPLETED`, `PARTIALLY_COMPLETED`, `FAILED`, `CANCELLED` |
| `COMPLETED` / `PARTIALLY_COMPLETED` / `FAILED` / `CANCELLED` | **نهائية — لا انتقالات** |

### 3.2 حالات الخطوة (10)

`PENDING`, `BLOCKED`, `READY`, `AWAITING_APPROVAL`, `RUNNING`, `SUCCEEDED`, `FAILED`, `RETRYING`, `SKIPPED`, `CANCELLED`.

**الانتقالات القانونية:**

| من | إلى |
| --- | --- |
| `PENDING` | `BLOCKED`, `READY`, `AWAITING_APPROVAL`, `SKIPPED`, `CANCELLED` |
| `BLOCKED` | `PENDING`, `READY`, `SKIPPED`, `CANCELLED` |
| `READY` | `RUNNING`, `AWAITING_APPROVAL`, `SKIPPED`, `CANCELLED` |
| `AWAITING_APPROVAL` | `RUNNING`, `READY`, `SKIPPED`, `CANCELLED` |
| `RUNNING` | `SUCCEEDED`, `FAILED`, `RETRYING`, `CANCELLED` |
| `FAILED` | `RETRYING`, `CANCELLED` |
| `RETRYING` | `RUNNING`, `FAILED`, `CANCELLED` |
| `SUCCEEDED` / `SKIPPED` / `CANCELLED` | **نهائية — لا انتقالات** |

> `FAILED` **ليست نهائية**: قد تُعاد المحاولة (`RETRYING`) أو تُلغى. النهائية هي `SUCCEEDED`/`SKIPPED`/`CANCELLED` فقط.

### 3.3 دوال التحقق

| الدالة | الغرض |
| --- | --- |
| `canTransitionRun(from,to)` / `canTransitionStep(from,to)` | استعلام منطقي بلا رمي |
| `assertRunTransition` / `assertStepTransition` | ترمي `409 CONFLICT` على انتقال غير قانوني، أو على `from === to`، أو على إعادة إحياء حالة نهائية |
| `assertStepSuccess(step)` | تمنع تسجيل خطوة `SUCCEEDED` بلا `result` |
| `assertRunCompletion(runStatus, steps)` | تمنع إكمال تشغيل وخطواته غير منتهية، أو بلا أي خطوة ناجحة، أو `COMPLETED` بينما بعض الخطوات لم تنجح |
| `resolveCompletionStatus(steps)` | تُرجع `COMPLETED` فقط إذا نجحت كل الخطوات، وإلا `PARTIALLY_COMPLETED` |
| `assertValidDependencies(steps)` | تتحقق من وجود كل تبعية، وعدم الاعتماد على الذات، وعدم وجود دورة (خوارزمية Kahn) |

**حماية الإحياء:** أي محاولة انتقال من حالة نهائية تُرفض افتراضيًا. الإحياء ممكن فقط بتمرير `{ allowReopen: true }` صراحةً (سياسة إدارية مقصودة) — ولا يمكن أن يحدث بالخطأ.
