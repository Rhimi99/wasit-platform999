# استيراد ملفات المطابقة المالية (Reconciliation File Import)

الملحق **أ.5-1** — استيراد تغذيات المطابقة من ملف بدل الإدخال اليدوي JSON.

> هذا الاستيراد **لا يحرّك أموالًا**. يسجّل **الدليل** (تغذية المزوّد/البنك) و**التصنيف** (MATCHED/MISMATCH) فقط،
> ولا يعتمد أي تسوية ولا يغيّر حالة Payout. الجانب الدفتري (ledger) **لا يُقبل من ملف** لأنه حقيقة داخلية.

## المسارات

| Method | Path | الأثر |
|---|---|---|
| POST | `/api/admin/finance/reconciliation/preview-file` | يتحقّق من الملف ويعيد تقرير المطابقة **دون كتابة أي صف** |
| POST | `/api/admin/finance/reconciliation/import-file` | يتحقّق ويسجّل الدليل + القرارات (نفس مسار JSON) |

- **الصلاحية**: `commission:manage` أو `payment:read` (وإلا 401/403).
- **الترميز**: `multipart/form-data`، ملف واحد تحت الحقل `file`.
- **سلسلة الاستعلام**: `source=PROVIDER|BANK` (إلزامي)، `currencyCode` (إلزامي، 3 أحرف ISO)،
  و`importKey`/`providerId` اختياريان للاستيراد فقط. أي قيمة `source` غير صحيحة ⇒ 422.

## الصيغ المقبولة

يُحدَّد النوع من **الامتداد** لا من `Content-Type`:

- `.csv` — فاصلة `,`
- `.tsv` — فاصلة جدولية `\t`
- `.json` — مصفوفة كائنات

CSV/TSV يتبعان RFC 4180: علامات اقتباس مزدوجة، حقول مسطّرة، أسطر `CRLF`، وتُزال BOM البادئة.

## الحدود الصارمة

| الحد | القيمة |
|---|---|
| حجم الملف | ≤ 1 ميجابايت (1,048,576 بايت) |
| عدد الأسطر (بيانات) | ≤ 5000 |
| الترميز | UTF-8 صالح (يُرفض أي ملف ثنائي/غير UTF-8) |

## الأعمدة

الترويسة إلزامية. تُقبل الأسماء التالية (مع تجاهل حالة الأحرف والشرطات/المسافات):

| الاسم المقبول | الحقل | إلزامي |
|---|---|---|
| `reference` / `ref` | المرجع | ✅ |
| `grossAmount` / `gross_amount` | إجمالي المبلغ | ✅ |
| `providerFee` / `fee` | عمولة المزوّد | ✅ |
| `netAmount` / `net_amount` | الصافي | ✅ |
| `currencyCode` / `currency_code` / `currency` | عملة السطر (تتجاوز عملة الملف) | لا |
| `settlementRef` / `settlement_ref` | مرجع التسوية | لا |
| `providerRef` / `provider_ref` | مرجع حركة المزوّد | لا |
| `payoutRef` / `payout_ref` | مرجع Payout | لا |

- **عمود مجهول** ⇒ رفض الملف بالكامل. هذا مقصود: أي محاولة لتهريب عمود دفتري (مثل `settled`)
  تُرفض بدل أن تُتجاهل بصمت.
- **عمود مكرّر** ⇒ رفض.
- **عمود مطلوب غائب** ⇒ رفض.

## قواعد السطر

- **المرجع**: مطلوب، لا يبدأ بـ`=`/`+`/`-`/`@` (منعًا لحقن صيغ جداول)، وفريد داخل الملف. المرجع المكرّر ⇒ رفض.
- **المبالغ**: أرقام عشرية غير سالبة. أي قيمة غير رقمية أو سالبة ⇒ رفض.
- **العملة**: عند وجودها يجب أن تكون 3 أحرف ISO، وإلا يُستخدم `currencyCode` الملف.

أي سطر مخالف **يرفض الملف بالكامل** (لا استيراد جزئي): الخطأ يعود بـ422 و`fieldErrors` يحدّد السطر والسبب.

## دلالة التصنيف

المعاينة/الاستيراد يُمرَّران بنفس محرّك `reconcile` مع **جانب دفتري فارغ** (الملف لا يحمل حقائق دفترية).
لذلك كل سطر يظهر `MISMATCH` بسبب `MISSING_IN_LEDGER` حتى يربط الاستيراد الدليل بصفوف دفترية حقيقية.
هذا هو الجواب الصادق: لا يُصطنع نجاح. ويبقى `MISMATCH` محفوظًا كما هو ولا يُرقّى إلى `MATCHED`.

## Idempotency

الاستيراد يمرّ بـ`importReconciliationFeed` نفسه: الـchecksum يُحتسب على الأسطر المصدرية.
إعادة رفع **نفس الملف** بنفس `importKey` تعيد نفس `importId` مع `duplicate=true` و`insertedLines=0`
ولا تُنشئ أثرًا ثانيًا.

## الواجهة

`/admin/finance` (بطاقة `admin-finance-reconciliation`): منتقي ملف + زر **معاينة** (لا يكتب) + زر **استيراد الملف**،
مع عرض ملخّص المعاينة (الصيغة/الصفوف/MATCHED/MISMATCH). المفاتيح: `adminFinance.reconFile*` في `ar/en/fr/zh`.

## الاختبارات

`packages/server/tests/reconciliation-file-import.test.ts` — 33 حالة على طبقتين:

1. **المحلّل النقي** (بلا قاعدة بيانات): كل الصيغ، الاقتباس/CRLF/BOM، تجاوز العملة، وكل حالات الرفض
   (الامتداد، الفراغ، الترميز، الترويسة، الأعمدة، الأرقام، الصيغ، التكرار، الحدود).
2. **المسارات الحقيقية** (تطبيق + قاعدة بيانات): 401/403، المعاينة لا تكتب، الاستيراد يحفظ `MISMATCH`
   ويكون idempotent، ورفض المرجع المكرّر وتهريب عمود `settled`.
